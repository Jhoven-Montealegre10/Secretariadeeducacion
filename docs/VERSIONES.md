## Política de actualización

1. **Mensual:** `npm outdated` y `npm audit`. Parches y menores de seguridad se aplican en una rama, con `npm run verify`
   (lint, formato, tipos, compilación, pruebas unitarias e integración con PostgreSQL, contrato OpenAPI y auditoría).
2. **Versiones mayores** (NestJS, TypeORM, Zod, Express): una a la vez, leyendo la guía de migración del proyecto,
   ejecutando además `npm run test:e2e` y `npm run test:load`, y desplegando primero en preproducción.
3. **Node.js:** mantenerse en una línea LTS. Revisar cada octubre (nueva LTS) y migrar antes del fin de vida.
4. **PostgreSQL:** actualizaciones menores en cada ventana de mantenimiento; mayores con `pg_upgrade` o restauración
   de `pg_dump`, probadas en preproducción con la copia anonimizada.
5. Nunca usar versiones beta/RC en producción; las versiones se fijan exactas (`--save-exact`) y el lockfile se versiona.
6. Tras actualizar, regenerar el OpenAPI si cambia (`npm run openapi:export`) y revisar el diff.
